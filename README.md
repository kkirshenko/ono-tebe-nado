# Проектная работа "Оно тебе надо"
Интернет-магазин с элементами аукциона, где пользователи могут:

- Просматривать товары в виде карточек
- Добавлять их в корзину
- Оформлять заказы и оплачивать их.
В нём можно посмотреть каталог товаров, добавить товары в корзину и делать заказы.

## Описание
В проекте ono-tebe-nado используется гибридный подход, сочетающий принципы MVP (Model-View-Presenter) и слоистой архитектуры. Вот как это работает:

Базовый слой (/base) — «Инфраструктура». При изменении данных в Model → событие через Events → View обновляет Component.

Общий слой (/common) — «Готовые блоки». Эти компоненты не чистые MVP, а скорее «умные блоки», сочетающие логику и отображение.

Слой приложения (/components) — «Ядро». Модифицированный MVP.

Проект использует адаптированный MVP с элементами Flux:
- Model (AppData, Model.ts) — централизованное состояние;
- View (Component, Page, Card) — рендер + пользовательские действия;
- Presenter (View.ts, Order, Basket) — посредники между Model и View.

## Описание базовых классов

### Класс `Component` является базовым абстрактным классом для всех компонентов и имеет следующие свойства и методы.

Методы:
- Реализует паттерн "Шаблонный метод" для единообразного создания компонентов;
- Добавление/удаление классов;
- Является родительским классом для всех View-компонентов.

### Класс `Model` -  это базовый класс для моделей данных, имеет следующие методы:

Методы:
- Инкапсулирует бизнес-логику приложения;
- Хранение состояния (data);
- Геттеры/сеттеры для полей модели;
- Механизм оповещения об изменениях.

### Класс `Api` -  это HTTP-клиент для работы с API, имеет следующие методы:

Методы:
- Обработчик ответа сервера;
- Принимает изменяющеюся часть url-адреса, возвращает ответ от сервера.

### Класс `Events` -  это система событий приложения, имеет следующие методы:

Методы:
- Реализует паттерн "Наблюдатель";
- Подписываться на события (on);
- Отписываться от событий (off);
- Генерировать события (emit);
- Используется для связи между компонентами.

### Класс `View` -  Базовый класс для представлений, имеет следующие методы:

Методы:
- Отображает интерфейс для взаимодействия с пользователем, отлавливает и сообщает о произошедших событиях;
- Наследует от Component.ts;
- Добавляет:
  * Связь с моделью данных (Model<T>);
  * Механизм обновления представления при изменении модели;
  * Автоматическую подписку на события модели;
  * Реализует паттерн "Наблюдатель" для синхронизации Model-View.
## Описание классов Common, которые содержат переиспользуемые компоненты верхнего уровня, которые:
Все компоненты наследуются от базовых (base/Component), используют EventEmitter для коммуникации и поддерживают динамическое обновление.
- Собираются из базовых компонентов (base);
- Реализуют сложную бизнес-логику;
- Используются в разных частях приложения;
- Инкапсулируют часто используемые паттерны интерфейса.

### Класс `Basket` - это компонент корзины покупок.

Методы:
- Отображает список добавленных товаров;
- Считает общую сумму заказа;
- Предоставляет методы:
  * addItem() - добавление товара;
  * removeItem() - удаление товара;
  * clear() - очистка корзины.

### Класс `Form` это универсальный компонент формы.

Методы:
- Поддерживает разные типы полей ввода;
- Реализует:
  * Валидацию данных;
  * Обработку сабмита;
  * Отображение ошибок.
- Используется для:
  * Формы заказа;
  * Формы оплаты;
  * Формы обратной связи.

### Класс `Modal` это модальное окно с расширенной функциональностью, наследуемое от base/Modal.

Методы:
- Поддерживает:
 * Динамический контент;
 * Автоматическое центрирование;
 * Затемнение фона;
 * Закрытие по клику вне области.

### Класс `Success` отображает успешное выполнение действия.

Методы:
- Показывает:
  * Иконку успеха;
  * Текст подтверждения;
  * Дополнительные данные (например, сумму заказа);
  * Автоматически закрывается через N секунд.

### Класс `Tabs` это компонент вкладок (табов).

Методы:
- Создаёт переключаемые вкладки (как в браузере или в меню);
- Анимацию переключения;
- Этот компонент отвечает только за переключение между вкладками, а что показывать при этом — решают другие части сайта.
## Классы, образующие «движок» интернет-магазина, где каждый отвечает за свою зону ответственности, но слаженно работает с другими частями системы.

### Класс `AppData` - Мозг проекта.

Методы:
- Хранит текущее состояние: список товаров, корзину, выбранные элементы;
- Координирует обновления интерфейса при изменениях.
Пример: При добавлении товара в корзину, Card отправляет событие в AppData, AppData обновляет состояние корзины, Page автоматически получает новые данные и обновляет счётчик.

### Класс `AuctionAPI` - Курьер.

Методы:
- Получает актуальные товары с сервера;
- Отправляет на сервер: ставки, заказы, контакты.
Пример:При открытии сайта Page запрашивает через AuctionAPI список лотов, после оформления Order отправляет данные заказа через этот же класс.

### Класс `Card` - Витрина.

Метод:
- Управляет отображением карточки товара на веб странице (Фото, названием, ценой, кнопкой действий ("Купить"/"В корзине").

### Класс `Order` - Касса.

Методы:
- Форма оформления заказа с полями:
  * Адрес доставки;
  * Телефон/email;
  * Способ оплаты;
  * Проверяет корректность данных.
Пример: пользователь заполняет форму, Order проверяет телефон/адрес, при успехе — отправляет заказ через AuctionAPI.
### Класс `Page` - Сцена.

Методы:
- Основа интерфейса:
  * Шапка с корзиной;
  * Основная сетка товаров.
- Обновляет счётчик корзины;
- Рендерит список карточек из полученных данных.
